## 設定と起動

この章のファイルはすべて ts-developer が作る（2 章の「作成担当」）。

| 項目 | 内容 | 対応要件 |
|---|---|---|
| `npm start` | `node src/main.ts`（シェルの機能を使わず、半角空白で区切った引数だけ） | FR-7, FR-11, NFR-6 |
| `npm run typecheck` | `tsc --noEmit` | NFR-4 |
| `npm test` | `node --test "test/**/*.test.ts"`（ダブルクォートで囲み、glob の展開を Node.js に任せる。Windows の `cmd.exe` と POSIX のシェルの両方で同じに動く） | NFR-4, TT-1 |
| `package.json` の `type` | `"module"` | `.claude/rules/coding.md` の 1 章 |
| `package.json` の `engines` | `{ "node": ">=24" }` | NFR-4 |
| `package.json` の `dependencies` | `{}`（空のオブジェクト） | NFR-4 |
| `package.json` の `devDependencies` | `typescript`（5.8 以上）、`@types/node`（24 系以上）だけ | NFR-4、`.claude/rules/coding.md` の 1 章 |
| `package.json` の `private` | `true`（公開しないパッケージ） | - |
| 環境変数 `TOMATIME_HOST` | 既定 `127.0.0.1`。M-6 が `net.isIP()` で検査 | FR-7 |
| 環境変数 `TOMATIME_PORT` | 既定 `3000`。M-6 が検査 | FR-7 |
| `Dockerfile` | 下の内容。リポジトリ直下 | FR-11 |
| `README.md`（リポジトリ直下） | 下の 2 つの節を含む | FR-9, FR-12 |

### tsconfig.json

```json
{
  "compilerOptions": {
    "target": "esnext",
    "module": "nodenext",
    "moduleResolution": "nodenext",
    "strict": true,
    "noEmit": true,
    "allowImportingTsExtensions": true,
    "erasableSyntaxOnly": true,
    "verbatimModuleSyntax": true,
    "types": ["node"]
  },
  "include": ["src/**/*.ts", "test/**/*.ts"]
}
```

- `include` に `test/` を入れ、`npm run typecheck` でテストも型検査する
- 上の項目のほかに型検査を厳しくする設定（例: `noUncheckedIndexedAccess`）を足すのは ts-developer の判断でよい。型ストリップで消せない構文を要する設定（`experimentalDecorators`、`emitDecoratorMetadata`）は有効にしない

### Dockerfile

```dockerfile
FROM node:24-slim
WORKDIR /app
COPY package.json ./
COPY src ./src
ENV TOMATIME_HOST=0.0.0.0
EXPOSE 3000
USER node
CMD ["node", "src/main.ts"]
```

| 行 | 理由 | 対応する受け入れ条件 |
|---|---|---|
| `FROM node:24-slim` | 公式 `node` イメージの 24 系（D-24）。`slim` を選んだ理由は 10 章 | FR-11-AC-1 |
| `COPY package.json ./`、`COPY src ./src` | 実行に要るのは `src/` と、`"type": "module"` を持つ `package.json` だけ。ランタイム依存がないため `npm install` を行わない（NFR-4）。`test/`、`docs/`、`.claude/` をイメージに入れない | - |
| `ENV TOMATIME_HOST=0.0.0.0` | 要件定義書の FR-11 の補足 | FR-11-AC-2 |
| `EXPOSE 3000` | D-21。`TOMATIME_PORT` を設定しない | FR-11-AC-2, FR-11-AC-4 |
| `USER node` | 要件定義書の FR-11 の補足 | FR-11-AC-2 |
| `CMD ["node", "src/main.ts"]` | exec 形式。要素を半角空白でつなぐと `node src/main.ts` で `scripts.start` と一致する。`ENTRYPOINT` を書かない | FR-11-AC-3, FR-11-AC-5 |

- 命令は 1 行で書き、行末の `\` を使わない。命令の名前は大文字（要件定義書の「Dockerfile」の命令の行）
- `TZ` を設定する `ENV`・`ARG` の行と、文字列 `/etc/localtime` を書かない（コメントにも書かない）（FR-11-AC-4）
- `.dockerignore` は作らなくてよい（`COPY` が 2 つの対象だけを指定するため）

### README.md（リポジトリ直下）

| 節の見出し | 書くこと | 書かないこと | 対応する受け入れ条件 |
|---|---|---|---|
| `## 生成 AI への指示文の例` | 指示文の例。文字列 `https://<公開ホスト>/?t=`、`毎回異なる`、`日本時間`、`YYYY-MM-DD HH:mm:ss`、`推測しない`、`200 以外`、`形式でない` をすべて含める。`?t=` の後ろは `<毎回異なる値>` のように書く | 具体的な日付・時刻の値（`[0-9]{4}-[0-9]{2}-[0-9]{2}` と `[0-9]{2}:[0-9]{2}:[0-9]{2}` に一致する文字列）。クエリの値の例にも日付・時刻を使わない | FR-9-AC-1, FR-9-AC-2, FR-9-AC-3 |
| `## Docker での起動` | イメージの作成 `docker build -t tomatime .`、起動 `docker run -d --name tomatime -p 127.0.0.1:3000:3000 tomatime`、停止 `docker stop tomatime`（要件定義書の NFR-8 の補足と同じコマンド） | `-p 3000:3000`、`-p 0.0.0.0:`、`-P `、`--network host`、`--network=host` を含む例と説明 | FR-12-AC-1, FR-12-AC-2 |

- 節の範囲は見出しの次の行から次の `## ` 見出しの前まで（要件定義書の FR-9 の補足）。2 つの節のほかの節（概要、開発の手順）を置いてよいが、上の「書かないこと」は 2 つの節の中だけでなくファイル全体で避ける
