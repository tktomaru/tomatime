## 未決事項

要件定義書と食い違う点、要件定義書だけでは決められない点。要件定義書の未決事項（U-3、U-4、U-5、U-6、U-9）は要件定義書の扱いのまま引き継ぎ、ここには載せない。

| ID | 内容 | 関係する要件 | 実装を止めるか |
|---|---|---|---|
| U-1 | NFR-5 の検証方法は「テストで確かめる」を含むが受け入れ条件 ID がなく、テスト名の決まり TT-2（受け入れ条件 ID を先頭に入れる）は NFR のテストの名前を定めていない。本書では、要件定義書を変えずに、テスト名の先頭に `NFR-5:` を入れたテスト 1 件とコードレビューで確かめることにした（AI が決定、暫定）。ハーネスの検査（`FR-n-AC-m` がテストにあること）には影響しない。この扱いでよいか、メインのセッションを通じてユーザーが判断する | NFR-5 | 止めない |
| U-2 | Node.js 24 の版によっては、`.ts` を直接実行すると型ストリップの `ExperimentalWarning` が標準エラー出力に 1 行出る可能性がある（AI の知識で、確かめていない）。出ても時刻を含まず、FR-7・FR-8 の受け入れ条件（行が「ある」・`listening:` の行が「ない」）に影響しない。出るかどうかは開発機での `npm start` と NFR-8 の手順 2 の `docker logs` で確かめる。抑止のための起動引数（`--disable-warning`）は、`scripts.start` と `CMD` の両方に同じ引数を足す必要があるため本書では入れない | NFR-4, NFR-8, FR-11 | 止めない |
| U-3 | 待ち受けの開始後に `http.Server` が `error` イベント（受け付けの失敗）を出した場合の扱いは要件定義書に定めがない。本書では処理を登録せず、その場合はプロセスが例外で終了する（終了コードは 0 以外）。時刻の形式の値は返らない（TS-5 に反しない）。扱いを決める場合は要件の追加が要る | FR-8, NFR-6 | 止めない |
