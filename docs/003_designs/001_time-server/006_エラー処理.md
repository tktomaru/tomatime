## エラー処理

どの段階で何が起きても、正確な時刻の形式で返さないことを示す。500 の応答はすべて、ステータス 500、`Content-Type: text/plain; charset=utf-8`、`Cache-Control: no-store`、`Content-Length: 16`、`Date` なし、本文 `time unavailable`（`HEAD` は本文なし）。以下「500」と書く。

| 発生箇所 | 事象 | 応答 | ログ | 対応要件 |
|---|---|---|---|---|
| M-1（取得元） | 例外を投げる（`Error` のインスタンス） | 500 | `time unavailable: source threw <name>: <message>` | FR-4, FR-10 |
| M-1（取得元） | `Error` のインスタンスでない値を投げる | 500 | `time unavailable: source threw non-error value` | FR-4, FR-10 |
| M-2 手順 1 | 取得元が有限の数でない値（`NaN`、`Infinity`、`-Infinity`、数でない値）を返した | 500 | `time unavailable: source returned non-finite value` | FR-4, FR-10 |
| M-2 手順 3 | 日本時間が `0001-01-01 00:00:00` より前か `9999-12-31 23:59:59` より後 | 500 | `time unavailable: source returned out-of-range value` | FR-4, FR-10 |
| M-2 手順 4〜5 | 換算・整形で例外、または整形結果が形式に合わない | 500 | `time unavailable: internal error <name>: <message>`（`Error` でなければ `internal error non-error value`） | FR-4, FR-10 |
| M-4 手順 2、5 | 405・200 の応答の内容の組み立てで例外 | 500 | `time unavailable: internal error ...`（同上） | FR-4, FR-10 |
| M-4 手順 6（`writeHead` の前・途中） | 送信で例外が起き、`headersSent` が false | 500 | `time unavailable: internal error ...`（同上） | FR-4, FR-10 |
| M-4 手順 6（`writeHead` の後） | 送信で例外が起き、`headersSent` が true | `res.destroy()` で接続を切る。本文は送られていない | `time unavailable: internal error ...`（同上） | FR-4, CD-4 |
| M-4 手順 8 | 1 行の組み立て（例: `name` の getter が例外）または書き込み先が例外を投げる | 500（変わらない）。プロセスは後の要求を処理し続ける | 出ない | FR-4, FR-10 |
| M-4 手順 9 | 500 の送信で例外 | `res.destroy()` で接続を切る | 手順 8 で出したもの | CD-4 |
| `process.stderr` | 書き込みの非同期のエラー（`error` イベント） | 影響しない（M-7 の起動手順 1 の空の処理で受け止める） | 出ない | FR-4 |
| Node.js の `http`（M-4 の前） | 解析できない、`Host` なし、ヘッダーの上限超過、`Expect` が `100-continue` 以外、受信の時間切れ | Node.js の既定（400、431、417、408）。本文なし、取得元を呼ばない | 出ない | FR-6 |
| M-4 手順 2 | メソッドが `GET` と `HEAD` 以外（取得元が例外を投げる状態でも） | 405（取得元を呼ばない） | 出ない | FR-5 |
| M-6 | 環境変数が妥当でない | 待ち受けない。終了コード 1 | 標準エラー出力に `startup failed: invalid <名前>` | FR-7 |
| M-7（`listen`） | 待ち受けに失敗（`EADDRINUSE`、`EADDRNOTAVAIL`、`EACCES` ほか） | 待ち受けない。終了コード 1 | 標準エラー出力に `startup failed: <code> host=<host> port=<port>`（`code` がなければ `UNKNOWN`） | FR-8 |
| M-7 | SIGINT・SIGTERM | 処理中の要求を待たずに終了コード 0 で終了。処理中の要求は応答なしで切断されうる | 出ない | NFR-6 |

- 500 の本文とヘッダーの値は固定の定数だけで作り、例外の内容、取得元の値、時刻を入れない（TS-5、FR-4）。例外のメッセージは 1 行（ログ）にだけ入る
- 前回の値、推定値、既定値で補う経路はない。前回の値を保持する変数がないため（3 章「状態を持たない」）、次の要求では取得元を改めて呼ぶ（FR-4-AC-7、FR-4-AC-8）
- Node.js の `clientError`、`checkContinue`、`checkExpectation`、`connect` のイベントに処理を登録しない。登録すると既定の応答（FR-6）や `CONNECT` の既定の切断（FR-5 の補足）が変わるため
- 待ち受けの開始後に `http.Server` が出す `error` イベントは要件定義書に定めがなく、本書では処理を登録しない（11 章の U-3）
