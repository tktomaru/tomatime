## 要件との対応

要件定義書のすべての FR-n / NFR-n を載せる。

| 要件 | 設計箇所（モジュール・処理） | 備考 |
|---|---|---|
| FR-1 | M-1, M-2, M-4、5 章「要求 1 件の処理」の手順 3〜6、「整形（M-2）」、4.2 節「応答」 | 1 回の要求で取得元を 1 回だけ呼ぶ。UTC+9 は 9 時間の加算、秒未満は `Math.floor` で切り捨て |
| FR-2 | M-4（`req.method` だけを読む）、3 章「要求の情報」 | パスを読まないため、不正なエンコードや長いパスも同じ応答 |
| FR-3 | M-4（`req.method` だけを読む）、3 章「要求の情報」 | クエリ文字列を読まない |
| FR-4 | M-2, M-3, M-4、5 章「要求 1 件の処理」の手順 7〜9、6 章 | 1 つの `try` で取得から送信までを囲み、どこで例外が起きても 500 か切断。`Date` は `res.sendDate = false` で付けない。1 行の書き込みの失敗は捨てる |
| FR-5 | M-4、5 章「要求 1 件の処理」の手順 2 | 取得元を呼ぶ前に判定する。`Allow: GET, HEAD` |
| FR-6 | M-5（`http.createServer` に設定を渡さない）、6 章 | `clientError`、`checkExpectation`、`checkContinue`、`connect` に処理を登録しない。時間切れの設定を変えない |
| FR-7 | M-6、M-7、5 章「起動」「環境変数の検査」 | 検査の順は `TOMATIME_HOST`、`TOMATIME_PORT` |
| FR-8 | M-7、5 章「起動」の手順 5 | `err.code` がなければ `UNKNOWN`。`process.exitCode = 1` で自然に終了 |
| FR-9 | 8 章「README.md」の `## 生成 AI への指示文の例` | 作成は ts-developer |
| FR-10 | M-4、5 章「要求 1 件の処理」の手順 6、9（`HEAD` は `res.end()`）、4.2 節「応答」 | ヘッダーと `Content-Length` は同じ条件の `GET` と同じ値。`HEAD` でも取得元を 1 回呼ぶ |
| FR-11 | 8 章「Dockerfile」、M-7（`CMD` の起動先） | 作成は ts-developer。`CMD` と `scripts.start` は `node src/main.ts` |
| FR-12 | 8 章「README.md」の `## Docker での起動` | 作成は ts-developer |
| NFR-1 | 3 章「状態を持たない」、M-4（ヘッダー）、7 章の NFR の表 | 時刻・本文はその要求の処理のローカル変数だけに置く |
| NFR-2 | M-2（UTC の getter だけ）、3 章「タイムゾーン」、8 章「Dockerfile」（`TZ` を設定しない） | 検証は FR-1-AC-12 とコードレビュー |
| NFR-3 | M-5 の `createTimeServer` の引数（`clock`、`writeErrorLine`）、待ち受けをしない M-5、7 章 | `process` に触れるのは M-7 だけ |
| NFR-4 | 2 章、8 章（`package.json`、`tsconfig.json`、`Dockerfile`） | 型ストリップで直接実行し、ランタイム依存なし |
| NFR-5 | M-4（`req.method` だけを読む）、3 章「要求の情報」、7 章の NFR の表 | テスト名の先頭を `NFR-5:` にする（11 章の U-1） |
| NFR-6 | M-7、5 章「停止」、8 章「Dockerfile」の exec 形式の `CMD` | `process.exit(0)`。処理中の要求を待たない |
| NFR-7 | M-1（`Date.now()` だけ）、3 章「外部への通信」 | 同期状態の判定・NTP の照会をしない |
| NFR-8 | 8 章「Dockerfile」「README.md」 | 利用者の手動の確認。結果は要件定義書の U-9 で受け取る |
