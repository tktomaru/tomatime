### NFR-8 の補足

手動の確認の手順（公開前に VPS で利用者が行う。要求はホストの 127.0.0.1 に送る）。

| 順 | 操作 | 確かめること |
|---|---|---|
| 1 | リポジトリ直下で `docker build -t tomatime .` を実行する | イメージの作成が成功する |
| 2 | `docker run -d --name tomatime -p 127.0.0.1:3000:3000 tomatime` を実行し、`docker logs tomatime` を読む | `listening: host=0.0.0.0 port=3000` の行がある |
| 3 | ホストで `TZ=Asia/Tokyo date '+%Y-%m-%d %H:%M:%S'` を実行し、続けて `curl -i 'http://127.0.0.1:3000/?t=1'` を実行する | ステータス 200、`Content-Type: text/plain; charset=utf-8`、`Cache-Control: no-store`。本文が正規表現 `^[0-9]{4}-[0-9]{2}-[0-9]{2} [0-9]{2}:[0-9]{2}:[0-9]{2}$` に一致し、`date` の値と同じか後の時刻で、差が利用者の許容範囲にある（C-11 の前提の確認。U-9） |
| 4 | `docker stop tomatime` を実行し、`docker inspect -f '{{.State.ExitCode}}' tomatime` を読む | `docker stop` が 10 秒を待たずに終わり、終了コードが `0` |
| 5 | `docker logs --timestamps tomatime` を読む | 各行の前に Docker が受け取った時刻が付く（FR-4 の補足で、1 行に時刻を含めない理由に使った前提の確認） |
| 6 | `docker rm tomatime` の後、`docker run` に `-e TZ=America/New_York` を付けて手順 2〜3 を行う | 手順 3 の本文が、同じ手順の `date`（`TZ=Asia/Tokyo`）の値と同じか後の時刻で、日本時間である |

- 手順 6 は環境変数 `TZ` の確認で、`/etc/localtime` の差し替えは手動の確認に含めない。`/etc/localtime` に依存しないことは NFR-2 のコードレビューと FR-11-AC-4（`Dockerfile` で設定しない）で確かめる
- 手順 3 の基準を「利用者の許容範囲」とするのは、OS の時計のずれを許容する（C-3）ためで、数値の基準は要求書にない
