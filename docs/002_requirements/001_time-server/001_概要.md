## 概要

生成 AI が Claude Code の WebFetch で公開 URL を HTTPS で GET し、利用者の VPS の nginx が HTTP に変換して渡した要求に対して、その時点の OS の時計の値を日本時間（UTC+9）にした `YYYY-MM-DD HH:mm:ss`（19 文字、末尾改行なし）を返す Node サーバーと、それを Docker のコンテナで動かす `Dockerfile`、生成 AI への指示文の例と Docker での起動の説明を作る（REQ-1、REQ-2、REQ-4、REQ-5、REQ-11、REQ-15）。HEAD 要求は GET と同じに扱い、本文を送らない（REQ-1、FR-10）。

最大のリスクは、OS の時計から取得した値と異なる時刻（保持した古い値、タイムゾーンの取り違え、例外時の既定値）を時刻の形式で返すことである（C-4）。これに対し、応答のたびに時刻を取得して保持しないこと（NFR-1）、OS とコンテナのタイムゾーンに依存せず UTC+9 で求めること（NFR-2、C-11）、取得・整形に失敗した経路では 500 と時刻を含まない固定のエラー文だけを返し、原因は応答ではなく標準エラー出力の 1 行に出すこと（FR-4、FR-10、REQ-14）、200・405・500 の応答にキャッシュ抑止のヘッダーを付けること（NFR-1）を要件とし、固定時刻と取得失敗を注入する受け入れ条件で完全一致を確かめる（NFR-3）。

コンテナでは `Dockerfile` で待ち受けアドレスを 0.0.0.0 にし、ホスト側は 127.0.0.1 のポート 3000 だけに公開する（D-26、FR-11、FR-12）。Docker を使う確認は利用者の手動確認とする（NFR-8）。WebFetch の保持を避けるクエリ文字列の付け忘れは Node サーバーでは防がず、指示文の例で防ぐ（D-9、FR-9）。WebFetch の振る舞いに関する未確認の前提 3 点とコンテナの時計の前提は、公開前後に確かめる（U-4、U-5、U-6、U-9）。
