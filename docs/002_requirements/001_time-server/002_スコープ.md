### 受け入れたリスク

| リスク | 内容 | 根拠 |
|---|---|---|
| クエリの付け忘れによる古い時刻 | 生成 AI がクエリ文字列を付けない、または前回と同じ値を付けると、WebFetch が保持した最大 15 分ほど古い時刻が渡りうる。Node サーバーでは見分けられず、対策は指示文の例（FR-9）だけになる | D-9、D-9 の補足、C-8 |
| 誤ったパス・第三者の呼び出しにも時刻が返る | 指示文の URL が誤っていても時刻が返り、誤りに気付けない。全世界に公開されるため、第三者が任意のパスを呼んでも時刻が返る。負荷への対策は利用者が Node サーバーの外で行う | D-13、D-13 の補足、D-4、D-7 |
| OS の時計のずれ | VPS の OS の時計（コンテナから見える時計）が実際の時刻とずれていると、ずれた時刻を返す | C-3、C-11 |
| コンテナの時計の前提 | コンテナから見える時計がホストのカーネルの時計と同じという前提は AI の知識で、確かめていない。確認は U-9 | C-11 |
| WebFetch の未確認の前提 | クエリ文字列を区別した保持、本文の書き換えの有無、5xx 応答の本文が渡るか、の 3 点は確かめていない。外れた場合の扱いは U-4、U-5、U-6 | C-8 の補足 |
| 待ち受けアドレスを 127.0.0.1 以外にした場合の直接到達 | 運用者が `TOMATIME_HOST` を変えると、Node サーバーに外から平文 HTTP で直接届く可能性がある。対策は利用者が行う | D-8、D-8 の補足、D-7 |
| コンテナのホスト側の公開を誤った場合の直接到達 | イメージは 0.0.0.0 で待ち受ける（FR-11）ため、利用者がホスト側を 127.0.0.1 以外（例: すべてのアドレス）に公開すると、Node サーバーにホストの外から平文 HTTP で直接届く。Docker が公開したポートはホストのファイアウォールの設定を通らない場合がある（AI の知識）。Node サーバーでは防がず、`README.md` の説明（FR-12）で正しい公開の方法を示す | D-26、D-7、FR-11 の補足 |
| nginx のキャッシュ | nginx でキャッシュを有効にし、Node サーバーの `Cache-Control: no-store` を無視する設定にすると、古い時刻が返りうる。nginx の設定は利用者が行う | REQ-7、C-9、D-7 |
| Node サーバーの停止中・停止時 | 停止中は時刻を得られない。停止の操作をしたとき、処理中の要求は応答を返さずに切断されうる（時刻の形式の値は返らない） | REQ-9、D-7、NFR-6 |
| 500 の 1 行に含まれる例外のメッセージ | 例外のメッセージをそのまま含めるため、メッセージに日時の文字列があればコンテナのログに出る。ログは運用者が読むもので、応答には入らない | REQ-14、FR-4 の補足 |
