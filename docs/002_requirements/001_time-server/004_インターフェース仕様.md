## インターフェース仕様

各項目の根拠と決定主体・状態は、「対応要件」の FR-n・NFR-n の行に記す。

### エンドポイント

| メソッド | パス | 説明 | 対応要件 |
|---|---|---|---|
| `GET` | 任意（`/` を含む。クエリ文字列の有無・値を問わない） | 現在時刻（日本時間）を返す | FR-1、FR-2、FR-3、FR-4 |
| `HEAD` | 任意（`GET` と同じ） | `GET` と同じステータスとヘッダーを返し、本文を送らない | FR-10 |
| `GET` と `HEAD` 以外（`CONNECT` を除く） | 任意 | 405 を返す | FR-5 |
| `CONNECT` | - | 応答を返さずに接続を閉じる（Node.js の既定） | FR-5 |

### 応答の一覧

判定は上の行から順に行い、最初に当てはまった行の応答を返す。

| 条件 | ステータス | 本文 | 対応要件 |
|---|---|---|---|
| 要求が HTTP として解析できない | 400 | なし（Node.js の既定の応答） | FR-6 |
| HTTP/1.1 の要求に `Host` ヘッダーがない | 400 | なし（Node.js の既定の応答） | FR-6 |
| 要求行とヘッダーの合計が 16 KiB を超える | 431 | なし（Node.js の既定の応答） | FR-6 |
| 要求の受信が Node.js の既定の時間切れ（`headersTimeout`、`requestTimeout`）を超える | 408 | なし（Node.js の既定の応答） | FR-6 |
| `Expect` ヘッダーの値が `100-continue` 以外 | 417 | なし（Node.js の既定の応答） | FR-6 |
| メソッドが `GET` と `HEAD` 以外 | 405 | `method not allowed` | FR-5 |
| メソッドが `GET` で、時刻の取得・整形に失敗する（FR-4 の補足の 4 条件） | 500 | `time unavailable` | FR-4 |
| メソッドが `HEAD` で、時刻の取得・整形に失敗する（FR-4 の補足の 4 条件） | 500 | なし | FR-10 |
| メソッドが `GET` で、時刻を取得・整形できる | 200 | `YYYY-MM-DD HH:mm:ss`（日本時間） | FR-1、FR-2、FR-3 |
| メソッドが `HEAD` で、時刻を取得・整形できる | 200 | なし | FR-10 |

### 応答ヘッダー

| ヘッダー | 値 | 付ける応答 | 対応要件 |
|---|---|---|---|
| `Content-Type` | `text/plain; charset=utf-8` | 200、405、500（`HEAD` への 200 と 500 を含む） | FR-1、FR-4、FR-5、FR-10 |
| `Cache-Control` | `no-store` | 200、405、500（`HEAD` への 200 と 500 を含む） | NFR-1 |
| `Content-Length` | 200 は `19`、500 は `16`、405 は `18`（`HEAD` への 200 と 500 も同じ値） | 200、405、500 | FR-1、FR-4、FR-5、FR-10 |
| `Allow` | `GET, HEAD` | 405 | FR-5 |
| `Date` | Node.js の既定の値（本要件では規定しない） | 200、405 に付く。500 には付けない（`HEAD` への応答も同じ） | FR-4、FR-10 |
| `ETag`、`Last-Modified`、`Expires` | - | どの応答にも付けない | NFR-1 |

- 400、408、417、431 は Node.js の `http` が要求の処理の前に返す既定のエラー応答で、上の表のヘッダーは付けない。ヘッダーは Node.js の既定のままとし、本要件では規定しない（FR-6）
- `Date` を付けない範囲は Node サーバーが返す 500 までで、nginx 経由で生成 AI が受け取る応答には nginx が自分の `Date` を付ける（FR-4 の補足）
- `Transfer-Encoding: chunked` を使わない（`Content-Length` を付ける応答）
- `HEAD` への応答の `Content-Length` は、同じ条件の `GET` で送る本文のバイト数を示し、本文は送らない（FR-10 の補足）

### 本文の形式

#### 200 の本文

文字単位で定義する。文字コードは UTF-8 で、すべて ASCII の文字のため 19 バイトになる。前後に空白・改行・BOM を付けない。`HEAD` への 200 では本文を送らない。

| 位置 | 内容 | 文字・桁数 | 例 |
|---|---|---|---|
| 1〜4 | 年（日本時間） | 半角数字 4 桁、ゼロ埋め。`0001`〜`9999` | 2026 |
| 5 | 区切り | `-`（U+002D） | - |
| 6〜7 | 月 | 半角数字 2 桁、ゼロ埋め。`01`〜`12` | 01 |
| 8 | 区切り | `-`（U+002D） | - |
| 9〜10 | 日 | 半角数字 2 桁、ゼロ埋め。`01`〜`31` | 05 |
| 11 | 区切り | 半角空白 1 つ（U+0020） | （空白） |
| 12〜13 | 時 | 半角数字 2 桁、ゼロ埋め、24 時間表記。`00`〜`23` | 08 |
| 14 | 区切り | `:`（U+003A） | : |
| 15〜16 | 分 | 半角数字 2 桁、ゼロ埋め。`00`〜`59` | 02 |
| 17 | 区切り | `:`（U+003A） | : |
| 18〜19 | 秒 | 半角数字 2 桁、ゼロ埋め、秒未満は切り捨て。`00`〜`59` | 03 |

#### 200 以外の本文

| ステータス | 本文（完全一致） | 文字数・バイト数 | 末尾改行 | 対応要件 |
|---|---|---|---|---|
| 500（`GET`） | `time unavailable` | 16 文字、16 バイト（ASCII） | なし | FR-4 |
| 500（`HEAD`） | なし | 0 バイト | - | FR-10 |
| 405 | `method not allowed` | 18 文字、18 バイト（ASCII） | なし | FR-5 |
| 400、408、417、431 | なし | 0 バイト | - | FR-6 |

200 以外の本文は半角数字を含まない（時刻らしい値を含めないため。C-7）。

### 返却例

UTC `2026-01-04T23:02:03.000Z` を取得したときの `GET` への 200 の本文（末尾改行なし）。

```
2026-01-05 08:02:03
```

時刻の取得元が例外を投げたときの `GET` への 500 の本文（末尾改行なし）。

```
time unavailable
```

### 環境変数

| 名前 | 既定値 | 妥当な値 | 妥当でないときの振る舞い | 対応要件 |
|---|---|---|---|---|
| `TOMATIME_HOST` | `127.0.0.1`（未設定のときだけ使う）。コンテナでは `Dockerfile` の `ENV` で `0.0.0.0` が設定される（FR-11） | Node.js の `net.isIP()` が `4` または `6` を返す文字列（判定の例は表の後の補足）。ホスト名（例: `localhost`）、空文字列、角括弧付きは不可 | 待ち受けず、標準エラー出力に `startup failed: invalid TOMATIME_HOST` を出し、終了コード 1 で終了する | FR-7、FR-11 |
| `TOMATIME_PORT` | `3000`（未設定のときだけ使う） | `1`〜`65535` の 10 進の整数で、半角数字だけからなり、先頭が `0` でない文字列。空文字列、符号、空白、小数点を含むものは不可 | 待ち受けず、標準エラー出力に `startup failed: invalid TOMATIME_PORT` を出し、終了コード 1 で終了する | FR-7 |

- `TOMATIME_HOST` の補足: 判定は Node.js の `net.isIP()` の結果に従い、値を変換しない（前後の空白を取り除かない）。Node.js 24 での主な結果は次のとおり
  - 妥当: `127.0.0.1`、`0.0.0.0`、`::1`、`::`、IPv4 射影アドレス（例: `::ffff:127.0.0.1`）、ゾーン ID 付きの IPv6（例: `fe80::1%eth0`）
  - 不可: 先頭が 0 の数を含む IPv4（例: `127.000.0.1`）、各数が 255 を超える IPv4（例: `999.0.0.1`）、角括弧付き（例: `[::1]`）、ホスト名、空文字列
- `TOMATIME_HOST` の判定に `net.isIP()` を使うのは、妥当な値を文字単位で一意にするためで、AI が決定した（適用中）。待ち受けに使えるかは判定せず、使えないアドレスは FR-8 の起動失敗になる
- `TOMATIME_PORT` の既定値 `3000` は人が明示決定（D-21）
- 待ち受けアドレスとポートを変える手段は環境変数だけとし、起動引数は使わない（D-8 の「環境変数など」の例に沿って AI が決定）。コンテナでは `docker run` の `-e` で上書きできる（Docker の環境変数の扱い）
- 変数名に `TOMATIME_` を付けるのは、同じ VPS・開発機のほかのプログラムが使う `HOST`、`PORT` の設定を取り違えないため（AI が決定）

### ログ・標準出力・標準エラー出力

| 出力先 | 出すとき | 形式 | 例 | 対応要件 |
|---|---|---|---|---|
| 標準出力 | 待ち受けを始めたとき（1 回） | `listening: host=<アドレス> port=<ポート>` と改行（LF） | `listening: host=127.0.0.1 port=3000` | FR-7 |
| 標準エラー出力 | 環境変数が妥当でないとき | `startup failed: invalid <環境変数名>` と改行（LF） | `startup failed: invalid TOMATIME_PORT` | FR-7 |
| 標準エラー出力 | 待ち受けに失敗したとき | `startup failed: <エラーコード> host=<アドレス> port=<ポート>` と改行（LF） | `startup failed: EADDRINUSE host=127.0.0.1 port=3000` | FR-8 |
| 標準エラー出力 | 500 を返したとき（`GET`、`HEAD` とも。応答 1 件につき 1 行） | `time unavailable: <原因>` と改行（LF） | `time unavailable: source threw Error: clock read failed` | FR-4、FR-10 |

500 のときの `<原因>` は、条件ごとに次の文字列にする（すべて ASCII。`<name>` と `<message>` は例外の値から作る）。

| 条件 | `<原因>` | 対応要件 |
|---|---|---|
| 時刻の取得元が `Error` のインスタンスを投げた | `source threw <name>: <message>` | FR-4 |
| 時刻の取得元が `Error` のインスタンスでない値を投げた | `source threw non-error value` | FR-4 |
| 時刻の取得元が有限の数でない値を返した | `source returned non-finite value` | FR-4 |
| 取得した瞬間の日本時間が有効範囲外 | `source returned out-of-range value` | FR-4 |
| 換算・整形・応答の作成で `Error` のインスタンスが投げられた | `internal error <name>: <message>` | FR-4 |
| 換算・整形・応答の作成で `Error` のインスタンスでない値が投げられた | `internal error non-error value` | FR-4 |

- `<name>` は例外の `name` プロパティ、`<message>` は `message` プロパティを、それぞれ `String()` で文字列にした値。`<message>` が空文字列なら、`<name>: ` の後ろは空になる（例: `source threw Error: `）
- `<name>` と `<message>` に含まれる CR（U+000D）と LF（U+000A）は、1 文字ずつ半角空白（U+0020）に置き換える。ほかの文字は変えない。これで 1 行に収める（要求書の申し送り「改行を含む原因を 1 行に収める方法」。AI が決定）
- 行の先頭に発生時刻を付けない。時刻の取得元が返した値を含めない（FR-4 の補足）
- 要求ごとのログは出さない（要求書に要求なし）
- 起動時の出力（表の 1〜3 行目）に時刻（タイムスタンプ）を含めない
- `<アドレス>` と `<ポート>` は、環境変数の値（未設定なら既定値）をそのまま出す
- コンテナで動かすときは、標準出力と標準エラー出力がコンテナのログになる（要求書の REQ-14 の解釈。`docker logs` で読める）

### Dockerfile

リポジトリ直下の `Dockerfile` が満たす条件。受け入れ条件（FR-11-AC-1〜FR-11-AC-5）は、次の「命令の行」を読んで確かめる。

- 命令の行: 前後の空白を除いた行のうち、空行と `#` で始まる行（コメント）を除いたもの。`FROM`、`ENV`、`EXPOSE`、`USER`、`CMD` の命令は 1 行で書き、行末の `\` による継続を使わない。命令の名前は大文字で書く

| 項目 | 条件 | 根拠 | 対応要件 |
|---|---|---|---|
| 基盤のイメージ | すべての `FROM` の行が、公式 `node` イメージで、タグの先頭が 24 以上の版の番号（例: `node:24-slim`）。レジストリ名を前に付けない | D-24、C-10 | FR-11 |
| 待ち受けアドレス | 行 `ENV TOMATIME_HOST=0.0.0.0` がある | D-26 | FR-11 |
| 待ち受けるポート | 行 `EXPOSE 3000` がある。`TOMATIME_PORT` を設定しない（既定の 3000 を使う） | D-21 | FR-11 |
| 実行する利用者 | 行 `USER node` がある | AI が決定（FR-11 の補足） | FR-11 |
| 起動するコマンド | 最後の `CMD` の行が exec 形式（`CMD ` の後ろが JSON の文字列の配列）で、配列の最初の要素が `node`。要素を半角空白 1 つでつないだ文字列が `package.json` の `scripts.start` と一致する。`ENTRYPOINT` の行がない | REQ-9、NFR-6（停止のシグナル） | FR-11 |
| タイムゾーン | `TZ` を設定する行（`ENV` または `ARG` で名前 `TZ` を設定する行）がなく、文字列 `/etc/localtime` を含まない | C-11、NFR-2 | FR-11 |
| 含めないもの | compose と nginx の設定を作らない | D-25 | FR-11 |
