### C-8 の補足

- 動作確認の内容（メインのセッション、2026-11-24）: 127.0.0.1:18765 で平文 HTTP の仮サーバー（Node）を起動し、Claude Code の WebFetch で `http://127.0.0.1:18765/probe-a`（2 回）と `/probe-b` を取得した。3 回とも `error:100000f7:SSL routines:OPENSSL_internal:WRONG_VERSION_NUMBER` で失敗し、サーバーのログに HTTP 要求は 1 件も記録されなかった
- 失敗の原因を「HTTP を HTTPS に変換して TLS で接続したため」とするのは AI の解釈である
- 保持は実測していない。保持がない場合でも、D-6 の方法は害がない

#### 未確認の前提

次の 3 点は、要求や決定の前提になっているが確かめていない。公開後に実際の WebFetch で確かめる（[背景・目的](001_背景・目的.md)の成功の目安、[要件定義への申し送り](009_確認事項.md#要件定義への申し送り)）。

| 前提 | 依存する ID | 前提が外れた場合の影響 |
|---|---|---|
| 「per URL」の保持が、クエリ文字列の違う URL を別の URL として扱う | D-6、REQ-7、REQ-11 | 毎回クエリを変えても保持された古い時刻が渡り、D-6 の方法が働かない。呼び出し方法の見直しが要る |
| 取得した本文をモデルが処理して生成 AI へ渡すときに、時刻の文字列が書き換わらない（要約・言い換え・桁の欠落がない） | REQ-2、REQ-4 | 生成 AI が受け取る値が Node サーバーの返した値と異なり、C-4 の趣旨が成り立たない |
| 5xx の応答でも本文が生成 AI に渡る | D-12、REQ-3 | エラー文が渡らず、生成 AI が取得失敗の理由を知れない。時刻の形式を返さない点（C-7）には影響しない |
