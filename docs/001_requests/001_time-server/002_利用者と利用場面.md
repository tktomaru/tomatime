## 利用者と利用場面

### 利用者・関係者

| 利用者・関係者 | 部署・拠点 | 利用環境・インフラ | 利用時間帯 | 人数・利用規模 | 業務・利用場面 | 役割・責任 | 関心・結果の使い方 | 根拠・確認先 |
|---|---|---|---|---|---|---|---|---|
| 生成 AI（呼び出し元） | - | Claude Code の WebFetch で、インターネット上の公開 URL を HTTPS で GET する | 利用者が生成 AI を使っている間 | 同時に動く生成 AI のセッション数は未確認 | 利用者の指示に従い、現在時刻が必要なときに公開 URL を呼び出す | 毎回異なるクエリ文字列を付けて呼び出し、受け取った値を参考の現在時刻として使う | 日本時間の現在時刻の文字列 | 依頼原文、D-3、D-4、D-6、D-11、C-8 |
| 利用者（指示する人） | 個人の開発環境 | 生成 AI ツールを動かす開発機（Windows 11） | 未確認 | 1 人（AI の解釈。依頼文に記載なし） | 生成 AI に、公開 URL から時刻を取得して参照するよう指示する | 成果物の指示文の例をもとに指示する。指示文でクエリの付け忘れを防ぐ（D-9）。生成 AI の出力を受け取る | 生成 AI が正しい現在時刻を前提に作業すること | 依頼原文「指示したい」、D-9、D-17 |
| 設置・運用者（VPS、Docker、nginx） | 個人で契約している VPS（ConoHa） | VPS（Linux の Debian。版は明示なし）、Docker、nginx。Node サーバーはコンテナ内で動き、ホスト側は 127.0.0.1 のポートに公開する。nginx が HTTPS を受けて HTTP に変換し、Node サーバーへ渡す | 常時（公開サーバーのため。AI の解釈） | 利用者と同じ人（AI の解釈） | Dockerfile からコンテナを作って動かす。VPS、nginx、TLS、公開側の対策（質問 D の文面で挙げた認証とレート制限を含む、公開に伴う対策のすべて）、ホスト側の公開、コンテナの常駐を設定する。500 の原因を標準エラー出力（コンテナのログ）で確かめる | Dockerfile 以外の設定は今回の作業範囲の外で、利用者が行う | Node サーバーが nginx からの HTTP 要求に応答すること。時刻を返せなかったときの原因 | D-4、D-7、D-18、D-22、D-23、D-25、D-26 |
| インターネット上の第三者 | - | 公開 URL に到達できる任意の端末 | 任意 | 不特定 | 公開 URL の任意のパスを呼び出しうる | 想定する利用者ではない | - | D-4（全世界に公開）、D-7（公開側の対策は利用者が行う）、D-13 |

### 利用の流れ

| 区分 | 順 | 担当 | 行動・判断 | 結果・引き継ぎ先 | 根拠 |
|---|---|---|---|---|---|
| 現状 | 1 | 生成 AI | 現在時刻が必要になっても取得できない | 推測した日時を使うか、利用者に尋ねる（AI の解釈） | 依頼原文「生成AIが時刻を取得できない」 |
| 変更後 | 1 | 設置・運用者 | Dockerfile からコンテナを作り、待ち受けアドレスに 0.0.0.0 を指定して起動し、ホスト側は 127.0.0.1 のポート 3000 に公開する。nginx から転送されるよう設定する | Node サーバーが nginx からの HTTP 要求を待つ | D-4、D-7、D-21、D-22、D-25、D-26 |
| 変更後 | 2 | 利用者 | 成果物の指示文の例をもとに、生成 AI に、公開 URL に毎回異なるクエリ文字列を付けて現在時刻を取得し、参照するよう指示する | 生成 AI が指示を受け取る | 依頼原文、D-6、D-9、D-17 |
| 変更後 | 3 | 生成 AI | 現在時刻が必要なとき、WebFetch で `https://<公開ホスト>/<任意のパス>?t=<任意の値>` を GET する | nginx が HTTPS で受ける | D-3、D-4、D-6、D-11、D-13 |
| 変更後 | 4 | nginx（対象外） | HTTPS を HTTP に変換して Node サーバーへ渡す | Node サーバーに HTTP の要求が届く | D-4、C-9 |
| 変更後 | 5 | Node サーバー | その時点の OS の時計の値を日本時間にして `YYYY-MM-DD HH:mm:ss`（末尾改行なし、`text/plain; charset=utf-8`）で返す | nginx を経て生成 AI が文字列を受け取る | REQ-1、REQ-2、D-2、D-5、D-14、D-15 |
| 変更後 | 6 | 生成 AI | 受け取った値を参考の現在時刻として作業に使う | 利用者が生成 AI の出力を受け取る | 依頼原文「参照するように」 |

### 異常・例外時の利用場面

| 区分 | 起きる条件 | 利用者・運用者への影響 | 期待する対応・代替手段 | 根拠・確認先 |
|---|---|---|---|---|
| 時刻の取得・整形の失敗 | OS の時計の値を取得または整形するときに例外が起きる、または値が返却形式に収まらない | 生成 AI が時刻を得られない | 時刻の形式や時刻らしい値を返さず、500 と時刻の形式を含まない短いエラー文を返す。原因を標準エラー出力に 1 行出し、運用者がコンテナのログで確かめる | REQ-3、REQ-14、C-7、D-12、D-23、要件定義への申し送り |
| Node サーバー停止中 | Node サーバーまたはコンテナが動いていない | nginx がエラーを返し、生成 AI が時刻を得られない | 生成 AI が時刻を取得できなかったと扱い、推測しない（指示文の例に書く）。常駐の仕組みは利用者が用意する | REQ-5、REQ-9、D-7、D-17 |
| 同じ URL での再取得 | 生成 AI がクエリ文字列を付けない、または前回と同じ値を付けて呼ぶ | WebFetch が保持した最大 15 分ほど古い時刻を渡す可能性がある。Node サーバーでは見分けられない | Node サーバーはクエリなしでも時刻を返す（D-9）。古さは指示文の例で毎回異なる値を付けさせて防ぐ（D-6、D-9、D-17） | C-8、D-6、D-9、D-17 |
| 誤ったパス | 指示と異なるパスへの GET | 誤った URL でも時刻が返り、誤りに気付けない | どのパスにも時刻を返す（D-13）。残るリスクとして受け入れる | D-13 の補足 |
| GET と HEAD 以外のメソッド | GET と HEAD 以外のメソッドで呼ばれる | 生成 AI や第三者が想定外の応答を受け取る | 応答は要件定義で定める。HEAD は GET と同じに扱い本文なしで返す（D-20） | REQ-1、D-20、要件定義への申し送り |
| 第三者からの大量の呼び出し | 公開 URL が不特定の端末から任意のパスで呼ばれる | VPS の負荷が増える | 認証とレート制限は利用者が Node サーバーの外（nginx を含む）で行う（Node サーバーの対象外） | D-7、D-13 |
| 待ち受けアドレスの変更・ホスト側の公開の誤り | 運用者がコンテナの外で 127.0.0.1 以外に待ち受けを変える、またはコンテナのポートをホストの 127.0.0.1 以外に公開する | Node サーバーに外から平文 HTTP で直接届く可能性がある | 公開側の対策として利用者が行う。ホスト側は 127.0.0.1 だけに公開する（D-26） | D-7、D-8、D-26 |
| ポートの使用中 | 起動時に待ち受けるポートを他のプログラムが使っている | Node サーバーが起動できない | 起動に失敗したことを運用者が分かるようにする。ポートを設定で変える（D-16） | REQ-13、[要件定義への申し送り](009_確認事項.md#要件定義への申し送り) |
| コンテナのタイムゾーン設定 | コンテナ内の `TZ` や `/etc/localtime` が日本時間以外になっている | タイムゾーンに依存すると返す時刻がずれる | 設定によらず同じ日本時間を返す（REQ-10、C-11） | REQ-10、C-11 |
| OS の時計のずれ | VPS の OS の時計が実際の時刻とずれている | 生成 AI がずれた時刻を受け取る | 許容する。サーバーは同期状態を判定しない | C-3 |
