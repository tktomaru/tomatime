## 用語集

要求書で共通して使う用語とデータ項目の意味をそろえる。指標の算出方法は[要求一覧](003_要求一覧.md)の指標 BOOK、データの取得元や実際の粒度は[データ検証結果](008_既存システムへの影響.md#データ検証結果)を参照する。

### 用語 BOOK

| 用語・データ | この要求書での意味・扱い | 関連する要求 | 根拠・確認先 |
|---|---|---|---|
| 現在時刻 | 要求を受けて応答を作るときに、Node サーバーが動くコンテナから見える OS の時計から取得した値。保持した値や推定値は含まない | REQ-1、REQ-7 | C-3、C-4、C-5、C-11 |
| 参考の現在時刻 | 生成 AI が作業の前提として使う時刻。OS の時計のずれを含みうる | REQ-1 | 依頼原文「参照するように」、C-3 |
| 正確な時刻が利用できる場合 | D-5 の原文の語。OS の時計の値を取得し、返却形式に整形できた場合を指す（AI の解釈） | REQ-2、REQ-3 | D-5 の補足、C-3 |
| 日本時間（JST） | UTC+9。夏時間はない。OS やコンテナのタイムゾーン設定に関係なく使う | REQ-1、REQ-10 | D-2、C-11 |
| 返却形式 | `YYYY-MM-DD HH:mm:ss` の 19 文字だけ。括弧なし、年 4 桁、月・日・時・分・秒は 2 桁ゼロ埋め、24 時間表記、日付と時刻の間は半角空白 1 つ、区切りは `-` と `:`、末尾改行なし。Content-Type は `text/plain; charset=utf-8` | REQ-2 | D-5、D-14、D-15 |
| 旧返却形式 | `【YYYY-MM-DD HH:mm:ss】`。2026-11-25 に `CLAUDE.md` と関連資材から括弧なしへ更新され、この要求書では使わない | REQ-2 | C-2、D-5、D-10 |
| 時刻らしい値 | 日付または時刻を表すと読める文字列のすべて。返却形式の文字列、推定値、前回値、既定値、エポック秒の数値、返却形式以外の書式の日時を含む | REQ-3 | C-7 |
| エラー文 | 時刻を取得・整形できないときに 500 とともに返す短い文字列。時刻の形式や時刻らしい値を含まない。文言は要件定義で定める | REQ-3 | D-12 |
| 標準エラー出力の 1 行 | 500 を返したときに、その原因を標準エラー出力に出す 1 行。応答の本文とは別。コンテナではコンテナのログになる。含める項目は要件定義で定める | REQ-14 | D-23 |
| HEAD 要求 | GET と同じに扱い、本文なしの 200 を返す要求 | REQ-1 | D-20 |
| Node サーバー | 今回作る、nginx から HTTP で要求を受けて時刻を返すプログラム。Docker のコンテナ内で動く | REQ-1、REQ-6、REQ-9 | D-4、D-7、D-22 |
| Dockerfile | Node サーバーを動かすコンテナを作るためのファイル。成果物に含める。compose と nginx の設定は含めない | REQ-15 | D-25 |
| 待ち受けアドレス | Node サーバーが HTTP の接続を受け付けるアドレス。既定は 127.0.0.1 で、設定で変えられる。Docker で動かすときは 0.0.0.0 を指定する | REQ-12 | D-8、D-26 |
| ホスト側の公開 | コンテナのポートを VPS のどのアドレスとポートに結び付けるかの設定。127.0.0.1 のポート 3000 だけに公開する（例: `-p 127.0.0.1:3000:3000`）。利用者が行う | REQ-12 | D-26 |
| 待ち受けるポート | Node サーバーが HTTP の接続を受け付けるポート。既定は 3000 で、待ち受けアドレスと同じ手段で変えられる | REQ-13 | D-16、D-21 |
| 公開 URL | 生成 AI が HTTPS で GET する、利用者の VPS の nginx が受ける URL。パスは任意（どのパスにも時刻を返す） | REQ-1、REQ-4、REQ-5 | D-4、D-13 |
| nginx | 利用者の VPS（ConoHa、Debian）で動き、HTTPS を HTTP に変換して Node サーバーへ渡すプログラム。設定は利用者が行う | REQ-4、REQ-6 | D-4、D-7、D-18、C-9 |
| 公開側の対策 | D-7 の説明文の語。公開に伴う対策のすべてを指し、質問 D の文面で挙げた認証とレート制限を含む。利用者が Node サーバーの外で行う | REQ-6 | D-7 |
| クエリ文字列 | URL の `?` の後ろの部分（例: `?t=<任意の値>`）。Web 取得ツールの保持を避けるため毎回変えるよう指示する。有無と値に関係なく時刻を返し、値は時刻の計算に使わない | REQ-11 | D-6、D-9 |
| 生成 AI ツール | 利用者が使う生成 AI のアプリケーション。Claude Code | REQ-4 | D-11 |
| Web 取得ツール | 生成 AI ツールが持つ、URL を指定して内容を取得する機能。この要求書では Claude Code の WebFetch だけを対象にする | REQ-4 | D-3、D-11、C-8 |
| 指示文の例 | 利用者が生成 AI に、公開 URL から時刻を取得して参照するよう伝える文章の例。成果物に含め、公開 URL の形、毎回異なる `?t=<任意の値>`、日本時間であること、取得できないときは推測しないことを書く。クエリの付け忘れを防ぐ唯一の手段になる | REQ-5 | 依頼原文、D-9、D-17 |
| 保持（ツール側のキャッシュ） | Web 取得ツールが同じ URL の取得結果を一定時間とっておき、再取得せずに渡すこと | REQ-7、REQ-11 | C-8、D-6、D-9 |
