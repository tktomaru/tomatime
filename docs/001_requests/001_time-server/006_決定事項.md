### 決定事項の補足

- D-1 は、質問 A への回答（D-4）で生成 AI が同じマシンではなく公開サーバーを呼ぶことになったため取り消し扱いにした。ユーザーが D-1 の取り消しを言葉で明示したのではなく、D-4 の内容と両立しないことによる AI の判断である。D-1 の「127.0.0.1 だけで待ち受ける」は引き継がず、待ち受けアドレスは D-8 で改めて決まった
- D-3 の Web 取得ツールは、D-4 により公開 URL を HTTPS で取得する前提に変わり、D-11 で Claude Code の WebFetch だけと決まった。ユーザーの原文は「WebFetchだけです。」で、「Claude Code の」は Q-1 の選択肢 A の文言による（AI の解釈）
- D-5 の原文の「墨付きかっこ」は、前の文の「全角の隅付き括弧」を指すと解釈し、質問 B で「括弧なしの 19 文字」が選ばれて確定した
- D-5 の原文の「正確な時刻が利用できる場合」は、C-3（OS の時計の値を正確な時刻とみなす）により、OS の時計の値を取得・整形できた場合を指すと解釈した（AI の解釈）。取得・整形できない場合は REQ-3 による
- D-5 に合わせた `CLAUDE.md` と関連資材の更新は、D-10 の指示でメインのセッションが 2026-11-25 に行った。末尾改行の記載も、D-19 の指示でメインのセッションが 2026-11-25 に「付けない」へ更新した（[既存システムへの影響](008_既存システムへの影響.md)）。両ファイルの変更記録は、Q-7 への回答「それ以外は推奨を採用する」と D-19 の指示を根拠にしている
- D-7 の決定内容は選ばれた選択肢の説明文の範囲に留めた。D-25 により、成果物の範囲に Dockerfile が加わった（「Node サーバーのみ」の範囲を人が変更した）。nginx・TLS・公開側の対策を利用者が行う点は変わらない
- D-7 の当時、質問 D で選ばれなかった選択肢「nginx の設定例も含める」「起動の仕組みまで含める」から、nginx の設定例と起動の仕組みを対象外とした（AI の判断）。D-25 の後の扱いは次のとおり。nginx の設定と compose は D-25 の説明文で対象外と明示された。Dockerfile は D-25 で対象になった。コンテナの常駐・自動起動（例: 再起動の方針、OS 起動時の起動）は D-25 に含まれず、引き続き対象外とする（AI の判断。人のレビューで確認）
- D-7 と質問 D の文面（「認証やレート制限をどこで行うかにも関わります」）から、認証（Q-11）と起動の仕組み（Q-9）は不要になったと扱う（AI の判断）
- D-8 の「環境変数など」は選択肢の説明文の例で、変更の手段（環境変数か起動引数か）は明示されていなかった。D-26 の説明文には `TOMATIME_HOST=0.0.0.0` が含まれる。この名前は要件定義書の案（AI が作成）に由来するもので、手段と名前の確定は要件定義で扱う（AI の解釈）。nginx が Node サーバーと同じ VPS にあるかは明示されていない
- D-8 で待ち受けアドレスを 127.0.0.1 以外に変えた場合、Node サーバーに外から平文 HTTP で直接届く可能性がある。その場合の対策は公開側の対策として利用者が行う（D-7。AI の解釈）。D-26 では、コンテナ内は 0.0.0.0 で待ち受け、ホスト側の公開を 127.0.0.1 に限ることで、外から直接届かないようにする
- D-9 は、推奨（エラーにする）と異なる選択である。残るリスク: 生成 AI がクエリを付け忘れる、または前回と同じ値を付けると、Web 取得ツールが保持した最大 15 分ほど古い時刻を「現在時刻」として受け取る。Node サーバーではこれを見分けられない。指示文（REQ-5、D-17）がこのリスクへの唯一の対策になる
- D-12、D-14、D-15、D-16、D-17 は、ユーザーが「それ以外は推奨を採用する」と回答し、未回答だった Q-n の推奨案を一括で採用したものである。推奨案の内容は AI が作ったもの（[確認事項](009_確認事項.md)の各 Q-n の推奨と理由）で、採用は人が明示した。どの Q-n が「それ以外」に当たるかは、メインのセッションの読み取りによる（Q-1、Q-5、Q-13 以外の未回答の Q-n）
- D-13 は、推奨（1 つのパスにだけ時刻を返す）と異なる選択である。残るリスク: 指示文の URL が誤っていても時刻が返り、意図しない呼び出しを見分けられない。全世界に公開されるため、第三者が任意のパスを呼んでも時刻が返る。原文に「GET であれば」とあるため、GET が時刻を返す条件であることも明示されたと扱う。HEAD は D-20 で決まった。HEAD と GET 以外のメソッドの応答は明示されておらず、要件定義で定める
- D-18 では、Debian の版は明示されていない。D-22 により Node サーバーはコンテナ内で動くため、Node.js の版は D-24（24 以上）に従い、ホストの Debian の版には直接依存しない（AI の解釈）
- D-20 の原文の「本文なしの 200 を返すか」は、要件定義書の U-8 の選択肢 B の文言である。「GET と同じに扱い」から、時刻を取得・整形できない場合の HEAD は GET と同じく 500 にする（本文なし）と解釈した（AI の解釈。要件定義で確かめる）
- D-21、D-23、D-24 は、要件定義書の未決事項（U-1、U-7、U-2）への回答で、要件定義書の案（AI が作成）を人が採用したものを含む
- D-22 の「どうせ」は、D-21 の既定ポートを 3000 にしてよい理由として添えられた発言である。Docker 内で動かすことは前提として明示されたと扱う
- 「OS の時計のずれは許容する」は `CLAUDE.md` と `.claude/rules/time-safety.md` に「ユーザーの判断」と記載があるが、今回の入力に発言の原文がないため D-n にせず、既存仕様として C-3 に記す
