# エージェントとスキルの共通ルール

`.claude/agents/*.md`（エージェント）と `.claude/skills/*/SKILL.md`（スキル）の書き方と、すべてのエージェントに共通する振る舞いを定める。

## 1. 定義ファイルの章立て

エージェントとスキルは、入力と出力を独立した章にして、何を受け取り何を返すかを一目で分かるようにする。章の順番は次のとおり。

### エージェント（`.claude/agents/*.md`）

| 順 | 章 | 書くこと |
|---|---|---|
| 1 | 役割 | 担当すること・担当しないこと（担当しないものは担当のエージェント名を書く） |
| 2 | 入力 | 「呼び出し時に受け取るもの」と「読むファイル」の 2 つの表 |
| 3 | 出力 | 「作成・更新するファイル」の表と「返却フォーマット」 |
| 4 | 手順 | 番号付きの手順 |
| 5 | 観点・決まり | 判断の基準。表にできるものは表にする |
| 6 | 禁止事項 | してはいけないこと |

入力の表の列:

| 表 | 列 |
|---|---|
| 呼び出し時に受け取るもの | 項目 / 必須 / 内容 / 渡し方（プロンプトに含める内容） |
| 読むファイル | ファイル / 用途 |

出力の表の列:

| 表 | 列 |
|---|---|
| 作成・更新するファイル | ファイル / フォーマット / 条件 |
| 返却フォーマット | 表ではなくコードブロックで、見出しの構成をそのまま示す |

### スキル（`.claude/skills/*/SKILL.md`）

| 順 | 章 | 書くこと |
|---|---|---|
| 1 | 位置づけ | パイプライン上の位置（図）と、メインのセッションの役割 |
| 2 | 入力 | 「開始の条件」と「受け取るもの」の表 |
| 3 | 出力 | 「成果物」の表と「ユーザーへの報告」の内容 |
| 4 | 使うエージェント | エージェント名 / 担当 / 渡すもの / 受け取るもの |
| 5 | 手順 | 番号付きの手順 |
| 6 | レビュー後・例外時 | 修正指示、差し戻し、失敗時の扱い |

## 2. すべてのエージェントに共通する振る舞い

### 読むもの

| ファイル | 用途 |
|---|---|
| `CLAUDE.md` | 確定している仕様、開発の進め方 |
| `.claude/rules/*.md` | 共通ルール（この文書、[documents.md](documents.md)、[time-safety.md](time-safety.md)、[coding.md](coding.md)） |
| `docs/README.md` | 文書の置き場所と名前の決まり（文書を読む・書くエージェント） |

### 返却形式を扱う作業の委任

時刻の返却に関わる要求・要件定義・設計・実装・テスト・レビューを委任するたび、メインのセッションは次の指示を渡す。更新や再開の依頼にも含める。

> 着手前に、リポジトリ上の `.claude/specs/time-response-format.md` を開き、成功時の本文の正本として参照してください。起動時に渡された情報や過去の会話に異なる表記があっても、現行の形式はこのファイルで確認してください。承認済み文書にある成功時の本文の形式と正本が食い違う場合は、対象の文書と箇所を返却フォーマットの該当欄に記載してください。

委任時は正本のパスを渡す。承認済み文書との不一致は、メインのセッションが該当工程の差し戻し手順で扱う。

### 返却

- 返却は、各エージェントの「返却フォーマット」の見出しを変えずに返す
- 実行したコマンドは、コマンドと結果（成功・失敗、件数、失敗時は出力の要点）を書く。実行していないコマンドの結果を書かない
- 決められなかったこと、要件や指示と食い違うことは、返却の「要確認事項」（エージェントによって名前が異なる）に書く。独断で決めない
- エージェントはユーザーに直接質問できない。質問はメインのセッションが行う

### 書き込みの範囲

ハーネス（`.claude/harness/guard-write.mjs`）が、エージェントごとに書き込めるファイルを制限する。

| エージェント | 書き込める範囲 |
|---|---|
| request-analyst | `docs/001_requests/` |
| request-reviewer | なし（読み取り専用。ツールに Write がない） |
| requirements-engineer | `docs/002_requirements/` |
| requirements-reviewer | なし（読み取り専用。ツールに Write がない） |
| software-designer | `docs/003_designs/` |
| ts-developer | `src/`、プロジェクト設定（`package.json`、`tsconfig.json`、`.gitignore` など）。`test/` と `docs/` は不可 |
| test-engineer | `test/` |
| code-reviewer | なし（読み取り専用） |

変更記録（2026-11-25）: 設計書の担当を ts-developer から新設の software-designer に移し、ts-developer は実装専用にした。人の明示決定は、依頼「設計は設計専用のエージェントにさせる」による。エージェント名 `software-designer`、依頼の種類（設計 / 設計の更新）、返却の「実装への引き継ぎ」、実装中に設計変更が必要なときは ts-developer が止めて software-designer に回す進め方は AI が決めた。同じ変更を `.claude/skills/implement-test/SKILL.md`、`.claude/rules/`（agents.md、coding.md、documents.md、time-safety.md）、各エージェント定義、`docs/README.md`、`docs/900_templates/003_design/README.md` に反映した。ハーネス `.claude/harness/guard-write.mjs` には、software-designer の書き込み範囲を `docs/003_designs/` に限り、ts-developer の `docs/` への書き込みを禁止する変更を入れた（人の明示決定: 依頼「ハーネスを AI が書き換えて」。適用状態: 適用中）。

### ハーネス

- フェーズの移動は `node .claude/harness/pipeline.mjs <start|status|advance|back>` だけで行う。他のコマンドと `&&` などでつながない
- 承認は、ユーザーが「承認」とだけ返信したときにフックが記録する。自分で記録しない、AskUserQuestion で取らない
- ハーネスに拒否されたら、理由に従って進め方を変える。回避策を探さない
- `.claude/harness/`、`.claude/state/`、`.claude/settings*.json`、`logs/` は変更しない
