## 残った指摘への対応

AI 一次レビューの指摘を反映した後、ユーザーが対応を選ぶ必要のある指摘が残ったとき、またはその選択への回答が返ったときに読む。確認事項に反映済みの論点は Q-n で尋ねる。すでに判断を受けた指摘は選択結果を報告に反映する。

| 順 | ユーザーに対応を選んでもらう対象 |
|---|---|
| 1 | 指摘の反映後に残った重大・高の指摘 |
| 2 | request-analyst が「対応しない」とした指摘 |
| 3 | request-reviewer と request-analyst の意見が分かれた点 |
| 4 | 残っている中・軽微の指摘 |

### AskUserQuestion

| 項目 | 決まり |
|---|---|
| 1 問 | 1 件の指摘または意見が分かれた点を尋ねる |
| question | 指摘 ID、重要度、対象箇所、判断したいこと、影響を示す。誤った時刻を返す余地につながる指摘は先頭に置き、質問文にその影響を書く |
| header | 指摘 ID と重要度を 12 文字以内で示す |
| options | 2〜4 個。推奨があれば先頭に置いて「(推奨)」を付け、選ぶと文書のどこが変わるかを description に書く。重大・高の指摘では見送りを推奨候補から外す |
| 1 回の呼び出し | 最大 4 問。5 件以上ある場合は重要度順に 4 問ずつ尋ねる |
| multiSelect | `false` |

選択肢には、指摘どおり修正する、案を採用する、確認事項（Q-n）に回す、今回は対応しないなど、論点に合う対応を入れる。意見が分かれた点には両者の案を示す。自由記入はツールの Other を使う。文書の承認は「承認」とだけ返信してもらう。

### 回答の扱い

| 回答 | 対応 |
|---|---|
| 修正・案の採用・Q-n への記録 | 指摘、選ばれた項目のラベル、description、メモを原文で request-analyst に渡す。反映結果か、新しい Q-n をユーザーに示す |
| 今回は対応しない | 指摘とユーザーの選択を人のレビュー依頼に記録する |
| Other の自由記述 | 原文を request-analyst に渡し、反映結果と残る確認事項を示す |
| ツールが使えない、拒否された、回答がない | 人のレビュー依頼に選択肢を示し、指摘 ID と選んだ対応をチャットで返信できるようにする |

回答から新たに先に決めるべき事項が分かったら [重要事項の確認](002_重要事項の確認.md) に進む。文書と残る論点の報告は [人のレビュー依頼](004_人のレビュー依頼.md) に従う。
