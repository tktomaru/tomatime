## 回答・差し戻しの反映

人のレビュー中に修正指示や回答を受けたとき、または要件定義から `back request` で戻したときに読む。

1. `request_review` での更新はそのフェーズで行う。`back request` の後は `request` で要求書を更新する。どちらも現在のパスは `pipeline.mjs status` で確認する。
2. 残った指摘への対応を選んだ返信は [残った指摘への対応](005_残った指摘への対応.md) の「回答の扱い」に従う。確認事項への回答や修正指示は、要求書のパス、質問とユーザーの返信の原文、該当する Q-n を添えて request-analyst に渡す。プロセス質問への回答も、根拠に沿って要求・決定事項・確認事項に反映する。要件定義から戻した場合は、差し戻し理由と影響する要求・要件 ID を添える。
3. 新たに先に決めるべき事項が分かった場合は [重要事項の確認](002_重要事項の確認.md) に進む。
4. 変更箇所と残る確認事項を [人のレビュー依頼](004_人のレビュー依頼.md) に従って示し、更新版の承認を求める。既存の一次レビュー結果を使って報告する。
