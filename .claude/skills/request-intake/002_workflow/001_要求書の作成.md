## 要求書の作成

パイプラインの新規開始、または `request` で初稿の作成を再開するときに読む。

1. 依頼文、これまでの回答、`CLAUDE.md` と依頼に直接関係する資料を確認する。先に決める必要がある未回答事項が見つかったら、[重要事項の確認](002_重要事項の確認.md) に進む。
2. 新規開始なら機能名を英小文字・数字・ハイフンで決め、`node .claude/harness/pipeline.mjs start <機能名>` を実行する。出力の「文書のフォルダ」の要求書のパスを使う。進行中の別の作業がある場合は `status` で確認し、どちらを進めるかユーザーに確認する。中止するときはユーザーが「中止」と返信する。
3. request-analyst に、依頼文、機能名、要求書のパス、先に聞いた質問とユーザーの回答・修正指示を渡し、[要求定義の 11 プロセス](008_要求定義の11プロセス.md) を順に進めさせる。依頼・質問・回答は原文で渡す。作成先とフォーマットは `docs/001_requests/<NNN>_<機能名>/` と `docs/900_templates/001_request/` に従う。
4. request-analyst から「今すぐユーザーに確認する事項」が返ったら、[重要事項の確認](002_重要事項の確認.md) に進み、回答と中断したプロセス番号を渡して続ける。質問済みの論点は回答の状態を引き継ぐ。
5. プロセス 11 の初稿がそろったら、[AI 一次レビュー](003_AI一次レビュー.md) へ進む。

要求の発見や例外の洗い出しに使うナレッジは、[要求定義のナレッジ](../001_request-definition/README.md) と request-analyst の定義から必要な章を選ぶ。
