## スキルと関連技術

| 分析で困っていること | 技法を選ぶヒント |
|---|---|
| 不満の原因や暗黙の判断が見えない | 観察、ヒアリング、因果分析で事実を集める。業務イベントを起点に整理すると、発生条件と業務ルールを発見しやすい |
| 利用の流れ、役割、受け渡しが曖昧 | 業務フローやユースケースでたどる。利用全体を見ながら範囲を絞るにはストーリーマッピングが向く |
| 同じ用語に別の意味がある | ドメインモデリングで用語と適用範囲を揃え、データ関係と粒度を確認する |
| 優先度や品質の根拠が弱い | 成功指標と対応を見送る影響を確認する。MoSCoW は採否を、非機能要求の分類は品質の観点を整理するのに使う |
| 実現性や受け入れ判断が揺れる | 判断を変える技術上の不明点を PoC で検証し、合意した振る舞いを確認条件に落とす |
| 変更の影響を追えない | 要求・決定・実現先を紐づける。追跡先が更新されなければ誤った影響分析につながる |
