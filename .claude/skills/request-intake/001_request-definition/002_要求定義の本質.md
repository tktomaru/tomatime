## 要求定義の本質

要求は依頼者の認識、記憶、言語化、伝達の各段階で欠けたり変わったりする。依頼の原文を残し、読み取った意図と照合できるようにする。

| 兆候 | 気づきと確認 |
|---|---|
| 口頭説明に出ない処理が実務にある | 当たり前の手順や忘れやすい例外は語られにくい。業務の流れ、記録、実物を材料に確かめる |
| 回答者の役割や同席者で説明が変わる | 部門ごとの実態や言いにくい事情かもしれない。個別に聞き、どの条件で各説明が成り立つかを確かめる |
| 同じ言葉から異なる振る舞いを読み取れる | 語の定義と対象、条件、成立の判定を確かめ、解釈を本人に確認する |

- 目的（Why）、必要な結果（What）、実現手段（How）を切り分ける。手段の指定には変更できるかと理由を確かめ、必須なら制約として記録する。
- 曖昧な品質や範囲は、対象・条件・判定基準のどれが未定かに分解する。後工程の判断を変えるものを確認事項にし、根拠のない値で埋めない。
