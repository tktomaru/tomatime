## 要求漏れを防ぐ技術

| 要求を知っている側 | 探し方 |
|---|---|
| 利用者と調査者の双方（公開） | 共有済みの前提も、条件と根拠を記録して認識を確かめる |
| 利用者のみ（秘密） | 実際の手順・履歴を追い、判断の理由と例外時の代替手順を聞く |
| 調査者のみ（盲点） | データや連携、品質の制約を、それが利用者に与える影響とともに伝える |
| 双方が未認識（未知） | 別の役割や有識者に聞き、仮説・実データ・条件の組み合わせから調べる |

- 直接利用者に加え、結果を受け取る人、設定や復旧を行う人も調べる。組織図より、実際の情報と作業の受け渡しをたどると漏れに気づきやすい。
- 仕様書、作業の観察、実データを照合し、用語・暗黙のルール・失敗時の手順を確認する。判断根拠が分からなければ、その業務やデータの責任者を探す。
- データの関係は双方向に、最小・最大件数を確かめる。未割り当て、複数所属、期間で変わる関係、関係自体が持つ属性を見落とすと、仕様が実態を表せない。
- 見つけた漏れは、発見に使った資料や観点とともに残す。同種の漏れが続く場合は調査項目やレビュー観点に取り込む。
