## 要点

- 依頼の原文・背景・期待する結果を押さえ、解釈を分けて記録する。同じ言葉でも、使う場面や判断基準が異なれば別の要求になる（002、011）。
- 実際の業務・資料・データを照合する。現場の回避手順、発言の食い違い、誰も説明できない境界に、暗黙の要求が残りやすい（003〜005）。
- 現状と望む結果の差から原因を探り、業務全体と例外を見たうえで必要な機能を考える。要求候補は広く集め、目的への寄与と見送る影響で絞る（006〜009）。
- 誤った成功、長期停止、データ損失の影響から必要な品質を考える。判断できない水準や前提は、影響と選択肢を添えて確認事項にする（010〜012）。
- 依頼と要求を双方向に照合し、抜けと根拠のない追加を探す。重要な不明点は後工程の判断に使える形で引き継ぐ（013〜017）。
