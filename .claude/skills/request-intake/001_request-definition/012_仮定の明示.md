## 仮定の明示

- 根拠が不足する前提は、候補・根拠・誤った場合の影響を確認事項にする。どの前提が変わると範囲、費用、受け入れ条件が変わるかを示すと、確認の優先度を決められる。
- 暫定で進む合意が取れたら、仮定の有効範囲、確認方法、担当、期限、成立しなかった場合の扱いを記録する。後工程で確定仕様と混同しないよう、影響を受ける要求と結びつける。
- 見積もりを比べるときは、対象範囲、データ量・増加率、負荷、品質、外部連携、移行・運用、作業分担の前提を揃える。前提が割れる場合は、見積もりの幅と変動要因を確かめる。
- 技術・製品・費用の知識が不足しているなら、情報提供依頼（RFI）や実現性の調査を先に行う。条件が揃ってから提案依頼（RFP）を行うと、提案の前提を比較できる。
