## 業務設計と例外処理

- トリガーから利用者が結果を使うまでを通し、担当、判断、情報の受け渡しを整理する。システムの境界を先に置くと、境界の外で担う承認、代替作業、復旧が抜けやすい。
- 通常の流れを起点に、入力不備、権限不足、依存先の失敗、途中の中断、再実行を照合する。利用者に見える結果、途中まで反映された状態、後から戻せるかを確かめる。
- 現行の制約で例外扱いされている正規業務は、必要な通常機能かを再評価する。頻度が低くても損失や安全への影響が大きい事象は先に決める。手作業に委ねる場合は担当、手順、業務を再開できる条件を確認する。
- 問題と要求を双方向にたどる。対応がない問題は要求漏れ、寄与先を説明できない要求は優先度を見直す手掛かりになる。採用・見送りは効果と残るリスクを示して判断を仰ぐ。
