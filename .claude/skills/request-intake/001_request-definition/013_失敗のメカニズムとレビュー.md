## 失敗のメカニズムとレビュー

- 納期を急いで曖昧な要求を通すと、後工程で解釈が分かれ、確認と再実装が増える。進みが遅いときは、仕様の矛盾、実現性不足、過大な範囲、作業の依存、納期設定のどれが原因かを見分ける。
- レビューでは依頼原文と成果物を項目ごとに突き合わせる。原文からは抜けを、成果物からは根拠のない追加を探す。指摘がない観点にも確認した箇所や根拠を残すと、形式だけのレビューを見抜ける。
- 指摘は該当箇所、根拠、起こり得る影響、対応案を結びつける。直せる記述と、利用者や責任者の判断が必要な論点を仕分け、後者は確認事項として扱う。
- 重大な不明点は、影響する作業を始める前に解消の判断を求める。修正後は指摘箇所と影響先を再確認し、残存する指摘と受容したリスクを承認者に伝える。
