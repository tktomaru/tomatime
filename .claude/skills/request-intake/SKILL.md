# 要求（パイプライン 1 / 3）

## 1. 位置づけ

要求定義の 11 プロセス → AI 一次レビュー 1 回 → 指摘の反映 → ユーザーレビュー → 要求確定 → 要件定義。

重要な未確定事項は発見時にメインのセッションが尋ねる。進行と承認は [エージェントの共通ルール](../../rules/agents.md)、出典と決定主体は [文書の共通ルール](../../rules/documents.md#41-根拠と決定主体) に従う。

## 2. 入力

新規システム・機能の依頼、または進行中の `request` / `request_review` が対象。依頼文、回答、修正指示、選択結果を原文で使う。小さな修正やバグ修正は該当の担当へ直接依頼する。

## 3. 出力

要求書は `docs/001_requests/<NNN>_<機能名>/` に置く。AI 一次レビュー結果は会話で扱い、人のレビュー依頼で要約する。パイプラインは `request_review` で人の承認を待つ。

## 4. 使うエージェント

要求書の作成・更新は request-analyst、読み取り専用の一次レビューは request-reviewer が担当する。メインのセッションは進行とユーザーへの確認を担う。

時刻の返却を扱う委任には、[返却形式を扱う作業の委任](../../rules/agents.md#返却形式を扱う作業の委任) の指示を含める。

## 5. 手順

`node .claude/harness/pipeline.mjs status` と会話の進捗から、**いま該当する行の手順だけを開く**。リンク先はその分岐に入った時点で読む。ナレッジは各手順から必要な箇所を参照する。

| いまの状況 | 開く手順 |
|---|---|
| 新規開始、または初稿の作成を再開する | [要求書の作成](002_workflow/001_要求書の作成.md) |
| 目的、範囲、利用が成立する条件、合意済み仕様を左右する判断が未回答 | [重要事項の確認](002_workflow/002_重要事項の確認.md) |
| 初稿がそろった、または AI 一次レビューの指摘を反映する | [AI 一次レビュー](002_workflow/003_AI一次レビュー.md) |
| 指摘や回答の反映が済み、人のレビューを依頼する | [人のレビュー依頼](002_workflow/004_人のレビュー依頼.md) |

同じ要求工程を再開するときは中断箇所から続ける。一次レビューを実施済みなら、受け取った結果を使う。

## 6. レビュー後・例外時

| いまの状況 | 開く手順 |
|---|---|
| 人のレビューへの回答・修正指示を受けた、または要件定義から `back request` で戻った | [回答・差し戻しの反映](002_workflow/006_回答・差し戻しの反映.md) |
| フックから要求書の承認を記録したと通知された | [承認後の引き継ぎ](002_workflow/007_承認後の引き継ぎ.md) |
| 同じ議論が続く、範囲が定まらない、回答が得られない | [トラブルシューティング](001_request-definition/014_トラブルシューティング.md) を読み、request-analyst に質問の絞り込みや選択肢の具体例を依頼する |

ハーネスに拒否されたら、その理由に従って対応する。
