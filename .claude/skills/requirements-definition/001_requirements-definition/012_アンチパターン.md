## アンチパターン

| 兆候 | 見直す判断 |
|---|---|
| 画面や技術が先に決まり、効果を説明できない | 目的と守るべき制約から、必要な振る舞いを引き直す |
| 一部の要件だけ細かく、未確認の業務が多い | 業務・データ・連携の全体に立ち返り、影響が大きい抜けから確かめる |
| 必須が多く、要求が対立する | 採らない場合に達成できなくなる目的を示し、費用・影響・依存で優先度を見直す |
| 品質目標が曖昧、または過剰 | 想定負荷と許容損失を出し、測定できる水準に調整する |
| 合意の直前に新しい要件が出る | 参加者、資料の事前確認、決める順序、外部確認の時期を見直す |
| 要件を変えたのにテストや運用が元のまま | 根拠と影響先のリンクをたどり、基準となる文書から更新する |
