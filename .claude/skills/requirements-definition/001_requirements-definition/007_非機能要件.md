## 非機能要件

| 観点 | 水準を決めるヒント |
|---|---|
| 可用性・復旧 | サービス時間と許容停止時間を定める。復旧に要する時間の目標（RTO）と、許容するデータ損失を時間で表す復旧時点の目標（RPO）を区別する |
| 性能・拡張性 | 負荷やデータ量、測定区間、応答時間の分布、処理量、将来の増加を確認する |
| 運用・保守性 | 検知、通知、対応の担当と、ログ・バックアップ・復元の要件を確認する |
| 移行性 | 移行対象、照合、許容停止時間と、切り戻す条件・手順を定める |
| セキュリティ | 主体・データごとの権限、保護、監査・保持の条件を確認する |
| 利用環境 | 利用機器・接続、アクセシビリティ、法令・設備・環境上の制約を確認する |

- 指標、対象範囲、測定時の負荷・環境、測定区間、除外条件、合否基準、検証方法を揃える。閾値だけでは異なる条件で測ってもどちらが正しいか判断できない。
- 業務が許容できる遅延、停止、損失から必要な水準を決め、根拠を残す。対策費と残る損失を比べる際も、安全・法令など満たすべき条件は確保する。
