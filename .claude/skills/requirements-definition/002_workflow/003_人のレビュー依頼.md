## 人のレビュー依頼

AI 一次レビューを終え、要件定義書をユーザーに提示するときに読む。人のレビューへの回答反映後もこの手順で報告する。

1. AI 一次レビューでユーザーの判断が必要な指摘や確認事項が残っている場合だけ、[残った指摘への対応](004_残った指摘への対応.md) に従う。回答済みの項目は選択結果を報告する。要求へ差し戻した場合は、差し戻し先で続ける。
2. フェーズが `requirements` なら `node .claude/harness/pipeline.mjs advance` で `requirements_review` に進める。形式検査で拒否されたら、理由を requirements-engineer に渡し、該当箇所の修正後に `advance` を再実行する。すでに `requirements_review` であれば、そのフェーズで報告する。
3. 次の内容を示し、要件定義書への人のレビューを待つ。重大・高の指摘が残る場合は先頭に示す。

| 項目 | 伝える内容 |
|---|---|
| 文書 | 要件定義書のパス |
| 仕様の要点 | 接点、入力条件、結果、失敗時や例外時の振る舞い。判断の根拠区分・参照先と決定主体・状態 |
| 要件 | 機能要件・非機能要件・受け入れ条件の件数、対象外とした要求 |
| 一次レビュー | 修正前のレビュー時点の判定、主な修正、残る指摘の重要度、確認できなかった範囲、ユーザーが選んだ対応。修正後の内容は人に確認してもらう |
| 未決事項 | U-n、種別、推奨。一次レビューで挙がったユーザーへの確認事項も示す |
| 依頼 | 内容でよければ「承認」とだけ返信してもらう。修正指示や回答も受け付ける |
