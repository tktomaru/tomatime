## 残った指摘への対応

AI 一次レビュー後に、ユーザーが判断する指摘や確認事項が残ったときに読む。チャットで指摘 ID と選択が返った場合は「回答の扱い」から進む。

重大・高、対応を見送った指摘と理由、ユーザーへの確認事項、エージェント間の意見の相違、中・軽微の順に示す。プロジェクトで最優先と定めたリスクに関わる指摘は先頭に置き、影響を書く。

### AskUserQuestion

- 論点ごとに一問、1 回につき最大 4 問の単一選択にする。header は指摘 ID と重要度を 12 文字以内で示す。question には指摘 ID、重要度、対象箇所、論点、影響を書く。
- 選択肢は 2〜4 個にする。推奨を先頭に置き、ラベルに「(推奨)」を付ける。description には要件や受け入れ条件への変更を示す。外部から見える出力が変わる場合は preview で違いを示す。
- 修正、見送り、未決事項への記録、要求への差し戻しから論点に合う案を示す。意見の違いがあれば比較できるようにする。重大・高では見送りを推奨候補から外す。自由記述は Other を使い、文書の承認は所定の返信で受け取る。

### 回答の扱い

| 回答 | 対応 |
|---|---|
| 文書の修正、未決事項への記録、Other | 指摘、選んだラベル、description、メモ、Other のうち該当するものを原文で requirements-engineer に渡す。更新後は、変更箇所と残る未決事項を [人のレビュー依頼](003_人のレビュー依頼.md) で示す |
| 見送り | 指摘と選択を人のレビュー依頼の報告に残す |
| 要求の変更が必要 | [要求への差し戻し](006_要求への差し戻し.md) に進む |
| ツールが使えない、拒否された、回答がない | 報告に選択肢を表で示し、指摘 ID と選択をチャットで返信してもらう。選択の確定は回答を待つ |

見送りや回答待ちの場合は [人のレビュー依頼](003_人のレビュー依頼.md) の報告に戻る。
